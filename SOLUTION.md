# Решение

## Сколько заняло

~1 ч

## Что сделано и что не успел

Сделано всё из частей 1–3 и один бонус — поиск по названию клуба.

- Экран: загрузка с `MATCHES_URL`, карточки (команды, счёт, дата в поясе устройства, статус по-русски), состояния загрузки / ошибки с «Повторить» / пустого списка.
- Фильтр Все / Предстоящие / Завершённые, кнопка «Обновить» + pull-to-refresh, «Обновлено N сек назад» (после минуты — «2 мин 35 сек»).
- Звёздочки в каждой карточке, оба бага из части 2 исправлены.

Не сделано: тесты, скелетоны вместо спиннера, `npx expo lint` не запускал.

## Решения

- **Структура.** Типы, загрузка и чистая логика (фильтр, поиск, форматирование) — в `src/matches.ts`, без React. Карточка — `MatchCard`, экран только держит состояние и собирает UI.
- **Фильтр.** «Предстоящие» = матчи, которые ещё не сыграны до конца: `scheduled`, `live` (счёт ещё может измениться) и `postponed` (будет сыгран позже). «Завершённые» = только `finished`. Неизвестный статус попадает только во «Все» с подписью «Статус неизвестен» — не угадываю категорию, но и не теряю матч.
- **Неочевидные случаи в данных:**
  - счёт `0 : 0` (m2) — проверяю `score === null`, а не falsy, иначе нули спрятались бы;
  - `startsAt: null` у перенесённого матча (m7) — показываю «Дата не назначена» (`new Date(null)` дал бы 1 января 1970);
  - время в UTC (`...Z`) — `toLocaleString('ru-RU')` без `timeZone` переводит в пояс устройства;
  - `live` с `minute` — показываю «Идёт · 67′»;
  - статус типизирован как известные значения + `string`, чтобы новый статус с сервера не ломал код.
- **Ошибки и fallback.** Проверяю `response.ok` и что в ответе есть массив `matches` (не-JSON или другой формат → ошибка). Если упала первая загрузка — полноэкранная ошибка с «Повторить». Если упало обновление — старые данные остаются, сверху строка с ошибкой. Пустой массив → «В этом туре пока нет матчей», пустой результат фильтра/поиска → «Ничего не найдено».
- **`MATCHES_URL`** в шаблоне содержал заглушку `OWNER/REPO` (404) — указал свой репозиторий.

## Баги из части 2

1. **Звёздочки.** Две причины. (а) `Boolean(favorites.indexOf(id))`: для отсутствующего id `indexOf` возвращает `-1`, а `Boolean(-1) === true` — поэтому горели все звёзды; у первого добавленного индекс `0` → `false`, и его звезда «гасла». (б) `toggle` мутировал массив стейта (`push`/`splice`) и передавал в `setFavorites` ту же ссылку — React сравнивает через `Object.is`, считает, что ничего не изменилось, и не перерисовывает; изменение всплывало при случайном следующем рендере, отсюда «непредсказуемость». → `includes` + новый массив через `filter` / spread в функциональном `setFavorites(prev => …)`. Дополнительно в `FlatList` передан `extraData={favorites}`, иначе строки списка не узнают, что избранное изменилось.
2. **«Обновлено N сек назад».** Колбэк `setInterval` создан один раз (`useEffect(..., [])`) и замкнул `seconds = 0` из первого рендера, поэтому каждую секунду выполнял `setSeconds(0 + 1)` — число застывало на 1. Проп `since` вообще не использовался, поэтому после обновления ничего не сбрасывалось; ещё интервал не очищался при размонтировании. → храню текущее время `now`, тикаю `setNow(Date.now())`, а секунды вычисляю как `now - since`; добавил `clearInterval` в cleanup.

## Как я использовал ИИ

Claude Code. Сначала разобрал задание и данные сам: нашёл ловушки (0:0, `startsAt: null`, `live`, заглушка в `MATCHES_URL`) и понял причины обоих багов из части 2 — `Boolean(-1)` и мутация стейта в `useFavorites`, устаревшее замыкание и неиспользуемый `since` в `UpdatedAgo`. Само написание кода и исправлений отдал агенту, задачи ставил пошагово, по коммиту на шаг. Каждый шаг проверял в браузере: звёзды переключаются независимо, фильтр, сброс счётчика после «Обновить», поиск, `npx tsc --noEmit`.

Где агент ошибся / не доделал:

- Первая проверка в браузере показала старую версию экрана без фильтров: агент запустил dev-сервер с `CI=1`, а в этом режиме Metro не следит за изменениями файлов. Заметил, потому что в браузере не появились новые элементы; перезапустили сервер без флага.
- После `npm install` агент получил изменённый `package-lock.json` (другая версия npm) и собирался закоммитить его вместе с правкой конфига — откатили, чтобы не тащить в историю шум, не относящийся к задаче.
- В первой версии `UpdatedAgo` агент показывал только секунды («Обновлено 345 сек назад») — попросил переписать на «5 мин 45 сек».

## Что улучшил бы, будь ещё 2 часа

- **Тесты** на `matchesFilter` / `matchesQuery` / `formatScore` / `formatAgo` (jest-expo) — логика уже вынесена в чистые функции без React, тестировать просто.
- **Сохранение избранного** между запусками через `@react-native-async-storage/async-storage`, с загрузкой в `useFavorites` при старте.
- **Скелетоны** вместо спиннера и анимация смены фильтра (`LayoutAnimation`).
- **Сортировка:** live сверху, затем по дате, перенесённые без даты — в конце.
- **Автообновление** live-матчей по интервалу (например, раз в 30 сек, пока есть `live`), с `AbortController` для отмены предыдущего запроса.
- **Runtime-валидация** ответа (zod), а не только проверка, что `matches` — массив.
- **Группировка по дням** с заголовками секций (`SectionList`) — тур растянут на неделю, так читается легче.
- Прогнать `npx expo lint` и добавить `.eslintrc` из `expo lint --init`.
